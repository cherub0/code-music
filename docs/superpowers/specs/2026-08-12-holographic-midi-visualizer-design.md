# 全息 MIDI 代码碎裂动画设计

## 1. 产品目标

构建一个面向桌面端 Chrome 和 Edge 的网页应用。用户选择一份音乐文件和与其匹配的 MIDI 文件后，应用通过 Three.js 播放一段赛博朋克风格的三维动画：悬浮代码框随音乐唤醒并破碎，代码碎片在空间中重组为全息五线谱和音符，随后随音乐继续演奏。用户可以校准音画同步、实时预览，并导出带声音的动画。

第一版优先验证“任意匹配的音乐与 MIDI 都能驱动同一套高质量视觉叙事”。它不包含从 MP3 自动扒谱，也不承诺移动端性能。

## 2. 用户体验

### 2.1 输入方式

- 用户从本地选择 MP3、WAV 或 OGG 音乐。
- 用户从本地选择对应的 MID 或 MIDI 文件。
- 应用提供至少一组允许再分发且已经校准的内置示例。
- 所有用户文件仅在浏览器本地读取，不上传服务器。

### 2.2 页面布局

- 左侧控制面板：音乐选择、MIDI 选择、同步微调、播放控制和导出入口。
- 中央全息舞台：占据主要视口的 Three.js 场景。
- 底部时间轴：显示播放进度，支持点击或拖动跳转。
- 导出期间，控制面板切换为分辨率、格式、进度、预计剩余时间和取消操作。

第一版支持键盘与鼠标。移动端布局、触摸操作和性能降级留到后续版本。

## 3. 视觉与演出设计

主视觉采用“全息乐谱舞台”：深色空间背景、青色与洋红色霓虹、半透明代码终端、环形全息结构、辉光和适度拖影。镜头沿乐句缓慢移动，避免频繁晃动影响观看。

动画分为四幕：

1. **代码唤醒**：代码终端悬浮出现；字符、扫描线和环境光随音乐脉冲。
2. **系统裂变**：预定触发点到来后，终端边框、面板和字符层分裂为可控碎片。
3. **碎片重组**：碎片沿带随机差异的弧线飞行，排列出五线谱骨架；部分字符和光点凝聚成标准音符模型。
4. **全息演奏**：乐谱沿空间纵深或弧面展开；播放指针推进，当前音符依据力度发光，镜头跟随当前乐句。

裂变和重组使用混合式方案。终端由程序可控的碎片组成，飞行轨迹通过确定性随机种子和缓动曲线预先计算，不引入完整物理引擎。MIDI 动态决定目标音符，因此不同曲目能复用同一套演出系统。

## 4. 系统架构

系统划分为以下边界清晰的模块：

### 4.1 资源输入模块

负责文件选择、类型与大小校验、对象 URL 生命周期和内置示例载入。对外输出经过验证的音频资源与 MIDI 二进制数据，不负责解析音乐内容。

### 4.2 MIDI 解析与规范化模块

解析轨道、拍号、速度事件、音高、起止时间和力度，并输出统一的音符事件模型：

```ts
type NoteEvent = {
  id: string;
  trackId: string;
  pitch: number;
  velocity: number;
  startSeconds: number;
  durationSeconds: number;
};
```

所有节拍与 tick 在此模块中转换为秒。渲染模块不直接理解 MIDI 原始结构。

### 4.3 同步与播放时钟模块

音频播放时间是实时预览的主时钟。模块统一处理播放、暂停、跳转、起始偏移和速度倍率，并向动画时间轴暴露当前逻辑时间。

拖动或跳转后，动画不依赖逐帧补算，而是根据绝对逻辑时间重建可见状态。这样可避免音画累计漂移。

### 4.4 乐谱布局模块

把规范化音符映射为三维目标：

- 音高决定垂直位置。
- 开始时间决定沿乐谱方向的位置。
- 时值决定音符持续高亮时间和可选的尾迹长度。
- 力度决定辉光、尺寸微调和脉冲强度。
- 音轨决定颜色细节或空间层级，但第一版只突出主旋律与伴奏的基本区分。

第一版的五线谱用于视觉化表达，不承诺达到可出版乐谱的完整排版规范。

### 4.5 Three.js 舞台模块

负责场景、相机、灯光、代码终端、碎片实例、五线谱、音符实例和后处理。大量重复碎片与音符使用 `InstancedMesh` 或等价的批量绘制方式。代码文本优先使用适合 WebGL 的高性能文字方案。

舞台只消费规范化时间和布局数据，不直接操作音频或解析 MIDI。

### 4.6 演出时间线模块

定义四幕之间的时间区间、相机轨迹、碎片状态和过渡曲线。默认根据曲目时长生成触发点，同时允许内置示例覆盖配置。随机行为必须可由固定种子复现，以支持稳定导出和测试。

**2026-08-13 最终审查修订（并非原始规则）：** 原始设计只说明触发点随曲目时长生成，随后实现计划把所有短于 20 秒的曲目笼统写成固定 `0 / 2 / 5 / 8` 秒边界。这个表述无法让 4 秒内置示例展示完整四幕，现明确修订为：

- 时长大于等于 20 秒：使用曲目时长的 `12% / 28% / 45%` 作为唤醒结束、裂变结束和重组结束点。
- 时长大于等于 8 秒且小于 20 秒：使用固定 `0 / 2 / 5 / 8` 秒边界，8 秒后进入演奏幕。
- 时长小于 8 秒：按比例压缩为曲目时长的 `20% / 50% / 80%` 边界，保留最后 20% 给演奏幕。4 秒内置示例因此在 `0.8 / 2.0 / 3.2` 秒切换，并能展示全部四幕。

### 4.7 导出模块

导出复用同一舞台、布局与演出时间线：

- 快速路径通过浏览器媒体捕获能力生成带音频的 WebM。
- 可选路径加载 FFmpeg/WASM，将 WebM 转换为 MP4。
- 支持 1280×720 和 1920×1080。
- 导出期间暂停交互修改，显示帧数、进度和预计剩余时间。
- MP4 转码失败时保留 WebM，并允许用户重新尝试。

导出能力在启动时进行检测。不支持相关浏览器 API 时，界面明确禁用对应格式，而不是在导出结束时才报错。

## 5. 数据流

1. 输入模块读取音乐和 MIDI。
2. MIDI 模块生成规范化音符事件。
3. 乐谱布局模块生成音符与谱线的三维目标。
4. 同步模块以音频时间为主时钟提供逻辑时间。
5. 演出时间线根据逻辑时间计算终端、碎片、相机和场景阶段。
6. Three.js 舞台渲染当前绝对状态。
7. 导出模块捕获同一场景和音频，输出 WebM，并按需转码为 MP4。

## 6. 同步校准

用户可以调整：

- 起始偏移：用于修正音乐开头留白或 MIDI 起点差异。
- 速度倍率：用于修正不同演奏版本的整体速度差异。

调整立即反映在预览中。第一版不实现自动动态时间规整，因此存在速度随时间变化的现场录音可能无法全程精确匹配；界面会说明这一限制。

## 7. 异常与恢复

- 文件类型错误或解析失败：指出具体文件和原因，保留另一份已成功载入的文件。
- 音频与 MIDI 时长差异明显：允许继续预览，但展示校准提醒。
- 空 MIDI 或无有效音符：阻止启动演出，并提示更换文件。
- 浏览器资源不足：建议切换 720p、关闭高成本后处理或减少粒子数量。
- WebM 捕获不可用：禁用导出并解释浏览器能力限制。
- MP4 转码失败：保留 WebM，释放 WASM 相关内存并提供重试。
- 用户取消导出：安全停止捕获、释放临时对象并恢复预览状态。

错误提示必须提供下一步操作，不只显示技术异常文本。

## 8. 性能策略

- 第一版目标平台为桌面端 Chrome 和 Edge。
- 使用实例化绘制减少碎片和音符的 draw call。
- MIDI 数据加载后预计算布局与轨迹，播放期间避免高频分配对象。
- 后处理效果设质量级别；预览可动态降级，导出使用用户选择的固定配置。
- 超长 MIDI 只创建当前时间窗口附近的可见音符，避免整首曲目同时进入场景。
- FFmpeg/WASM 按需加载，不增加首次预览的启动成本。

## 9. GitHub 与素材管理

- 使用 GitHub 管理源代码、设计文档、任务和版本。
- `.superpowers/`、构建产物、依赖和日志不进入仓库。
- 内置音乐、MIDI、字体和三维素材必须记录来源与许可证。
- 不提交用户选择的本地文件。
- 大体积且允许分发的示例素材是否使用 Git LFS，在素材确定后依据仓库大小决定。

## 10. 测试与验收

### 10.1 自动化测试

- MIDI tick、速度变化与秒数转换。
- 音符事件规范化与无效 MIDI 处理。
- 起始偏移、速度倍率、跳转和暂停后的逻辑时间。
- 音高、时值、力度和音轨到三维布局属性的映射。
- 固定随机种子产生可复现的碎片轨迹。
- 导出能力检测、取消和失败后的状态恢复。

### 10.2 端到端与人工验收

- 内置示例和本地音乐加 MIDI 均可完成载入与播放。
- 播放、暂停和拖动后，音频与音符动画保持同步。
- 四幕叙事完整且阶段切换无明显跳变。
- 当前音符的位置、持续时间和辉光与 MIDI 数据一致。
- 校准参数修改后可立即预览。
- Chrome 和 Edge 各完成一次完整预览与导出。
- 720p 与 1080p WebM 均能下载并包含可播放音频。
- MP4 可成功转码并在常见播放器中播放。
- MP4 失败后 WebM 仍可下载。
- 文件不匹配、资源不足和解析失败均显示可恢复提示。

## 11. 第一版明确不做

- 从 MP3、WAV 或 OGG 自动识别并生成 MIDI。
- 移动端适配和性能保证。
- 服务端上传、云存储、账号或作品社区。
- 可出版级的完整乐谱排版。
- 对速度持续漂移的不同演奏版本进行自动逐段对齐。
- 通用视频编辑器或自由关键帧编辑。

## 12. 完成定义

当上述桌面端输入、校准、四幕演出、实时同步、WebM 导出、可选 MP4 转码、异常恢复和测试要求全部通过时，第一版视为完成。
